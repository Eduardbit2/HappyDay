# HappyDay

Семейное web-приложение для дней рождения и персональных Telegram-напоминаний.
Требования и последовательность разработки: [PLAN.md](PLAN.md).

## Текущее состояние

Готовы авторизация и управление семейными аккаунтами, web-календарь,
редактирование и архив, группы, CSV, Telegram-бот и личные напоминания.
Отсчет дней общий для web и Telegram; доступен однократный вечерний повтор.
При старте миграции применяются автоматически с backup существующей базы.
Добавлены GitHub Actions и проверочная Docker-сборка; приемка развертывания
на Synology остается отдельным этапом. [Проверки CI](docs/ci.md).

Визуальная система: [дизайн и проверка](docs/design/system.md).

Первый администратор и правила входа: [Авторизация](docs/authentication.md).

Подробности, команды миграций и восстановление: [База данных](docs/database.md).

## Первый запуск на Windows (PowerShell)

Используем Python **3.12.10** и uv **0.12.10**. Версия Python закреплена
в `.python-version`, зависимости — в `uv.lock`.

```powershell
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install uv==0.12.10
.\.venv\Scripts\uv.exe sync --locked --cache-dir .uv-cache
Copy-Item .env.example .env
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe -m app.auth create-admin --name "Администратор" --login admin
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --no-proxy-headers --no-access-log
```

Копируйте `.env.example` только при первой настройке, чтобы сохранить свои настройки.
Активация `.venv` и изменение ExecutionPolicy не требуются.
Команда create-admin нужна один раз: она попросит пароль со скрытым вводом.
Откройте <http://127.0.0.1:8000/login>. Остановка — `Ctrl+C`.
Для автоматического перезапуска при разработке добавьте `--reload`.

Всегда используем один worker: этот же процесс запускает
Telegram polling и планировщик. Access log отключен, чтобы одноразовые
коды в URL не попадали в журнал. Доверие к заголовкам прокси для локального
запуска отключено; production-настройка будет подготовлена с Compose.

## Проверки

```powershell
.\.venv\Scripts\uv.exe lock --check --cache-dir .uv-cache
.\.venv\Scripts\ruff.exe check .
.\.venv\Scripts\ruff.exe format --check .
.\.venv\Scripts\python.exe -m pytest -q
```

Если после переключения между Windows sandbox и обычным пользователем pytest
сообщает об отказе в доступе к старому временному каталогу, используйте новый
каталог внутри проекта (не изменяя права системного Temp):

```powershell
New-Item -ItemType Directory -Path test-results -Force | Out-Null
$testRunPath = Join-Path (Get-Location) ("test-results/pytest-" + [guid]::NewGuid().ToString("N"))
.\.venv\Scripts\python.exe -X utf8 -m pytest -q -p no:cacheprovider --basetemp $testRunPath
```

Тесты проверяют lifecycle/readiness, недопустимый Host, конфигурацию production
и UTF-8 в HTTP-ответе, `.env` и SQLite, включая `ё` и emoji.
Проверяются также миграции, backup/restore, ограничения БД и откат транзакций.
Рабочие данные не используются.

`/health/live` возвращает `200`, пока сервер отвечает.
`/health/ready` возвращает `200` после старта и `503`, если приложение не готово.
Readiness проверяет lifecycle, доступность SQLite и актуальность revision.
Endpoint пока не сообщает о готовности Telegram.

## Настройки

Параметры приложения имеют префикс `APP_`; `.env` читается в UTF-8.
Переменные процесса имеют приоритет над `.env`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_ENV` | `development` | `development`, `test` или `production` |
| `APP_BASE_URL` | `http://127.0.0.1:8000` | Базовый адрес приложения |
| `APP_ALLOWED_HOSTS` | `["127.0.0.1","localhost"]` | Список хостов в формате JSON |
| `APP_DATA_DIR` | `./data` | Каталог SQLite и backups |
| `APP_LOG_LEVEL` | `INFO` | Уровень логирования приложения |
| `APP_SESSION_HOURS` | `168` | Абсолютный срок сессии в часах |

В production обязателен HTTPS, а хост `APP_BASE_URL` должен присутствовать
в `APP_ALLOWED_HOSTS`. Пустой список и wildcard запрещены. Все изменяющие
формы авторизации проверяют CSRF и Origin; cookie в production получает Secure.

Календарные расчеты используют `Europe/Moscow` через `zoneinfo`;
`tzdata` закреплена для поддержки Windows. `TZ` в `.env.example` отражает
целевую зону развертывания и не меняет системные часы Windows.

## Дни рождения, группы и CSV

Все активные участники семьи могут редактировать общий список. В карточке записи
доступны редактирование и перемещение в архив; архив открывается из общего списка.
Архивные записи можно восстановить. Окончательное удаление требует отдельного
подтверждения и удаляет также историю напоминаний этой записи.

В настройках групп можно изменить название, emoji, цвет и порядок. Удаление группы
требует выбрать другую группу для переноса всех записей, включая архивные.
Системную группу «Без группы» нельзя удалить или переименовать.

«Настройки → Импорт и экспорт» позволяет скачать все записи или загрузить CSV.
Формат: UTF-8 с BOM или без него, разделитель `;`, заголовок:

```text
name;day;month;year;group;note;active
```

`year` может быть пустым, пустая `group` означает «Без группы», `active` равен `1`
для календаря или `0` для архива. Стандартные CSV-кавычки позволяют использовать
точки с запятой и переносы строк в заметках. Загрузка ограничена 256 КБ и 500 записями;
большие файлы нужно разделить с сохранением заголовка. Без JavaScript CSV можно
вставить в текстовое поле. Некорректную кодировку при выборе файла браузер отклоняет.

Сначала проверяется весь файл и показывается предпросмотр, новые группы и возможные
дубли (включая совпадения с архивом и внутри файла). Импорт добавляет записи, не
обновляет существующие. Дубли требуют отдельного подтверждения. Одноразовый
предпросмотр действует 15 минут и привязан к текущей сессии; новый предпросмотр
заменяет предыдущий. Повторная проверка дублей и вся запись выполняются атомарно.
Группы сопоставляются по нормализованному названию без учета регистра; при нескольких
одноименных группах используется самая ранняя. Отсутствующие группы создаются.

Экспорт включает UTF-8 BOM для Excel. Текстовые ячейки, похожие на формулы или
начинающиеся с апострофа, получают дополнительный апостроф; импорт HappyDay снимает
это экранирование. Это правило следует учитывать при подготовке CSV вручную.
CSV содержит только дни рождения и названия групп; для полного восстановления
аккаунтов, настроек групп и журнала нужен SQLite backup.

Миграция `0003_csv_drafts` добавляет только временные предпросмотры. При старте
существующей базы автоматически создается backup перед обновлением. Откат к
`0002_auth` удаляет только незавершенные предпросмотры, сохраняя семейные данные.

Проверка реальных форм в Edge на отдельной тестовой базе:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/check_auth_browser.py
```

Сценарий проверяет авторизацию, редактирование, архив/восстановление, группы,
CSV, подтверждение удаления и отсутствие горизонтального скролла на 320–1280 px.


## Движок напоминаний

Планировщик работает внутри единственного процесса приложения, проверяя очередь
каждые 30 секунд. Его можно отключить через `APP_SCHEDULER_ENABLED=false`.
Правила: за 7 дней, за 1 день и в день рождения в 09:00 по `Europe/Moscow`.
После простоя обрабатываются события текущего московского дня до 00:00;
старые напоминания не догоняются. 29 февраля переносится на 28 февраля в
невисокосный год; при неизвестном годе возраст не показывается.

Получатели — активные пользователи с Telegram-привязкой, именинники — только
активные. Дата, активность и наличие привязки проверяются снова перед каждой
попыткой. Архивирование и изменение даты отменяют ожидающие доставки. Отмененные
доставки этого же события автоматически не возобновляются после восстановления
записи; следующие интервалы и ежегодные события создаются по обычным правилам.
Отключение аккаунта/привязки отменяет ожидающую отправку при ближайшей проверке.
Уже начатый сетевой запрос невозможно отозвать архивированием.

Очередь и результаты хранятся в SQLite. Уникальный ключ исключает повторное
создание одной доставки. Каждая попытка получает номер; успешная доставка больше
не отправляется. Сетевой вызов выполняется вне транзакции БД. Подтвержденные
временные отказы повторяются через 1, 5, 15 и 60 минут, максимум 5 попыток;
`retry_after` может увеличить задержку. Повторы не выходят за границы дня.

Timeout или обрыв соединения может означать, что сервис уже доставил сообщение.
Поэтому неизвестный результат, включая незавершенную отправку после сбоя процесса,
переходит в ошибку без автоматического повтора. Зависшая отправка обнаруживается
через 5 минут. Это предотвращает слепой повтор, но допускает пропуск сообщения:
гарантии «ровно один раз» через внешний API нет. История доступна администратору
в «Семья → Журнал напоминаний» с фильтром по статусу. Сырые ошибки транспорта,
токены и URL API в журнал не записываются.

Если токен Telegram не настроен, очередь рассчитывается, но не отправляется
и не помечается успешной. Контракт `Sender.send` принимает
сообщение с Telegram ID, текстом и ссылкой на карточку и требует сетевой timeout
не более 30 секунд. При завершении приложения цикл дожидается текущей попытки
и не начинает следующую. Telegram-адаптер и подтверждаемая привязка подключены.
Readiness web-приложения пока не проверяет работу Telegram.


## Подключение Telegram

1. Создайте бота через [BotFather](https://t.me/BotFather) и сохраните его токен
   в локальном `.env` как `APP_TELEGRAM_TOKEN=...`. Пустое значение отключает
   интеграцию. Рабочий токен не должен попадать в Git, логи или переписку.
2. Перезапустите приложение. Оно проверит бота через `getMe` и начнет long polling.
   Webhook и дополнительный входящий порт не требуются. Для этого токена должен
   работать только один процесс; существующий webhook нужно предварительно отключить.
   Приложение не удаляет webhook самостоятельно.
3. Откройте «Профиль → Telegram и личные напоминания», создайте ссылку и перейдите
   по ней в личный чат с ботом. Нажмите «Запустить». Ссылка действует 10 минут,
   показывается один раз; новая ссылка заменяет предыдущую.
4. Вернитесь в web-профиль, нажмите «Проверить запрос», сверьте имя и Telegram ID,
   затем подтвердите свой аккаунт. Само открытие ссылки не дает доступа к данным.
5. Нажмите «Отправить тестовое сообщение» и проверьте личный чат. Web сообщает
   только о запросе теста, а не о гарантированной доставке. Напоминания отправляются
   по расписанию; общую очередь показывает административный журнал.

В подтвержденном личном чате работают `/start`, `/menu`, `/test`,
ближайшие события, общий список, поиск по имени и группы. Бот выводит до пяти
записей за запрос; полный список доступен в web. Добавление работает пошагово прямо в чате; настройки открывают web-профиль. `APP_BASE_URL` должен быть доступен с устройства,
на котором открыт Telegram: адрес `127.0.0.1` указывает на само это устройство.

Добавление, редактирование, быстрый ввод и архивирование работают прямо в Telegram.
Вечернее напоминание остается следующей частью этапа 7.

При отключении через web бот теряет доступ к семейным данным, а ожидающие
напоминания пользователя отменяются. Заблокированные аккаунты также не получают
доступ. Уже выполняемый сетевой запрос отозвать нельзя. Кандидат привязки хранится
до подтверждения отдельно; завершение исходной web-сессии отзывает его.

Миграция `0004_telegram_pairing` добавляет временные запросы и курсор обновлений,
сохраняя аккаунты и готовые привязки. Перед обновлением автоматически создается
SQLite backup. При откате теряется курсор: повторное включение может повторно
показать ответы на старые updates. Действия с базой и сохранение курсора выполняются
в одной транзакции; ответы отправляются после commit. Если ответ оборвался, он
автоматически не повторяется — пользователь может повторить команду меню.

Проверки используют `httpx.MockTransport` и отдельную SQLite; browser-runner
явно отключает Telegram даже при наличии токена в локальном окружении или `.env`.
Контракт API: [Telegram Bot API](https://core.telegram.org/bots/api),
[deep links](https://core.telegram.org/bots/features#deep-linking).


### Ввод и редактирование в Telegram

- «🎂 Добавить» или `/add` запускает шаги: имя → день и месяц → год → группа →
  заметка → предпросмотр. Год и заметку можно пропустить; группу выбирают по номеру.
- Быстрый ввод `Иван Петров 17.05.1985` или `Иван Петров 17.05` сразу открывает
  предпросмотр. Для изменения группы/заметки используйте «↩️ Назад».
- В результатах поиска доступны «✏️ Изменить», «🗑 В архив» и ссылка на web-карточку.
  При редактировании можно оставить текущее значение каждого поля.
- «↩️ Назад» возвращает предыдущий шаг. «✖️ Отмена», `/cancel`, `/menu` и
  `/start` закрывают черновик без сохранения. Повторное «🎂 Добавить» показывает
  текущий незавершенный шаг вместо удаления введенных данных.
- Запись появляется только после нажатия кнопки под предпросмотром. Совпадение
  имени и даты, включая архив, требует отдельного подтверждения дубля.
- Черновик живет 15 минут с начала диалога, сохраняется при перезапуске и удаляется
  при отключении Telegram. Старые кнопки привязаны к версии черновика и не могут
  повторно сохранить запись. При потере ответа после сохранения проверьте список:
  операция и курсор входящих updates фиксируются атомарно до отправки ответа.
- Если запись изменили или удалили через web во время редактирования, бот завершит
  устаревший диалог и предложит открыть запись заново, не затирая чужие изменения.

Миграция `0005_bot_drafts` добавляет только черновики. Автоматический backup
перед обновлением сохраняется; откат удаляет незавершенные диалоги, сохраняя
готовые записи, Telegram-привязки и курсор polling.

В списках и карточках web, а также результатах поиска и меню Telegram отображается
срок до ближайшего дня рождения: «Сегодня», «Завтра», «Через N дней» с русским
склонением. Расчет общий для обоих интерфейсов, по дате Москвы; после прошедшего
дня рождения берется следующий год, 29 февраля в невисокосный год — 28 февраля.
В Telegram срок соответствует моменту запроса: для обновления нажмите меню снова.

### Вечерний повтор

В новых личных напоминаниях доступна кнопка «⏰ Напомнить вечером».
Нажмите ее до 19:00 МСК в день получения напоминания: бот подтвердит дополнительную
отправку на 19:00 этого дня. Проверка очереди выполняется каждые 30 секунд.
Повторное нажатие не создает дубль; кнопка доступна только получателю исходного
напоминания. В вечернем сообщении остается ссылка на карточку без новой кнопки повтора.

Запрос сохраняется в SQLite и переживает перезапуск. После простоя отправка
догоняется до конца того же московского дня; на следующий день отменяется.
Архивирование, изменение даты, отключение Telegram или блокировка пользователя
отменяют ожидающую отправку. При подтвержденном временном отказе действуют обычные
retry и предел пяти попыток; неизвестный результат не повторяется автоматически.

Администратор видит запросы и историю в «Журнале напоминаний» → «Вечерние повторы».
Миграция `0006_evening_reminders` добавляет две таблицы без изменения исходных
доставок. Перед обновлением создается автоматический backup. Откат удаляет только
