# HappyDay — итоговый план разработки

HappyDay — небольшое семейное web-приложение для хранения дней рождения и персональных напоминаний. Решение строится как один легковесный Python-сервис с адаптивным интерфейсом на Bootstrap, Telegram-ботом и SQLite; развертывание выполняется одним Compose stack через Dockhand на Synology.

## Зафиксированные решения

- У каждого члена семьи отдельный аккаунт.
- Регистрация закрыта: пользователей создает или приглашает администратор.
- Все авторизованные пользователи видят и могут редактировать общий список дней рождения.
- Группы нужны только для организации, фильтрации и визуальных меток; они не ограничивают доступ.
- Каждый именинник относится ровно к одной группе, включая системную группу «Без группы».
- Напоминания приходят каждому пользователю лично.
- Автоматические персональные уведомления отправляются только через Telegram.
- Пользователь без Telegram работает через web-интерфейс и не получает автоматические уведомления.
- Telegram работает через long polling, поэтому публичный webhook и отдельный входящий порт не нужны.
- Web-интерфейс публикуется через обратный прокси Synology. Домен, сертификат и правило прокси пользователь настраивает самостоятельно.
- Контейнером и Compose stack управляет Dockhand; сам Dockhand остается доступным только из домашней сети или VPN.
- В первой версии используется один контейнер приложения, один процесс и SQLite. PostgreSQL, Redis и отдельный worker не требуются.
- Для локальной разработки используется стандартное Python-окружение `.venv`; внутри production-контейнера отдельное виртуальное окружение не создается.
- Приватный GitHub-репозиторий является единственным источником истины для кода, Compose-конфигурации, миграций и документации.
- Dockhand получает проект как Git Stack из ветки `main` по read-only deploy key; production deploy запускается вручную.
- GitHub Actions выполняет проверки и тесты, но не развертывает приложение автоматически.
- Секреты, рабочая SQLite, резервные копии и персональные данные никогда не попадают в GitHub.
- Интерфейс и данные полностью поддерживают русский язык и UTF-8.

## Scope

### Входит в первую версию

- Закрытая семейная авторизация и управление пользователями.
- Общий список именинников с добавлением, редактированием, архивированием и поиском.
- Группы с названием, иконкой, цветом и порядком сортировки.
- Главная страница с ближайшими событиями и возрастом, когда известен год рождения.
- Персональное подключение и отключение Telegram.
- Telegram-бот с кнопочным меню и пошаговым добавлением данных.
- Напоминания за 7 дней, за 1 день и в день рождения в 09:00 по `Europe/Moscow`.
- Журнал доставок, повторные попытки и защита от дублей.
- Импорт и экспорт CSV в UTF-8.
- Docker Compose, healthcheck, резервное копирование и инструкция для Dockhand/Synology.
- Автоматические backend-, integration- и browser-тесты.
- Локальная `.venv`, закрепленные зависимости, приватный GitHub-репозиторий и CI в GitHub Actions.

### Не входит в первую версию

- Нативное Android/iOS-приложение.
- PWA Web Push и установка сайта как приложения.
- Telegram Mini App.
- Общий Telegram-чат как канал уведомлений.
- Права доступа к отдельным именинникам или группам.
- Несколько групп у одного именинника.
- Синхронизация с телефонными контактами, Google Calendar и другими календарями.
- Фотографии, списки подарков, поздравительные тексты с ИИ и социальные функции.
- PostgreSQL, Redis, Celery, Kubernetes и микросервисная архитектура.
- Автоматический production deploy по push/webhook, публичный доступ к Dockhand и обязательная публикация образов в сторонний registry.

## Архитектура

```text
Телефон или браузер
        │
        │ HTTPS
        ▼
Reverse Proxy Synology :443
        │
        │ HTTP 127.0.0.1:8787
        ▼
HappyDay container :8000
├── FastAPI web/API
├── Jinja + HTMX + Bootstrap UI
├── aiogram Telegram long polling
├── APScheduler reminder engine
└── SQLAlchemy + SQLite /data/happyday.db
        │
        └── /data/backups — согласованные снимки БД

HappyDay ── исходящий HTTPS ──► Telegram Bot API
```

Приложение запускается одним процессом и одним worker. Это принципиально: при нескольких web-worker каждый экземпляр запустил бы свой планировщик и Telegram polling. Масштаб семьи не требует горизонтального масштабирования, а один процесс существенно упрощает эксплуатацию.

Backend разделяется на внутренние модули, а не на отдельные сервисы:

- `app/web` — страницы, формы, сессии и HTTP-маршруты;
- `app/bot` — Telegram-команды, кнопки и пошаговые сценарии;
- `app/birthdays` — правила работы с именинниками и группами;
- `app/notifications` — расчет получателей и доставка через Telegram;
- `app/scheduler` — поиск наступивших напоминаний, retry и catch-up;
- `app/auth` — пользователи, пароли, приглашения и привязка Telegram;
- `app/db` — модели, подключения и миграции;
- `templates` и `static` — Jinja-шаблоны, Bootstrap, иконки и стили;
- `tests` — unit-, integration- и browser-тесты.

## Среда разработки и синхронизация с GitHub

- Инициализировать Git в корне проекта и создать приватный GitHub-репозиторий `HappyDay`.
- Использовать стандартное окружение `.venv` только на компьютере разработчика; каталог полностью исключить через `.gitignore`.
- Описывать прямые зависимости и dev-инструменты в `pyproject.toml`, а точные проверенные версии фиксировать в lock-файле. Docker и локальная разработка должны использовать одну закрепленную версию Python и один набор зависимостей.
- Хранить в Git исходники, шаблоны, локальные статические ресурсы, миграции, тесты, `Dockerfile`, `compose.yaml`, `.env.example`, документацию и CI workflow.
- Исключить из Git `.venv`, `.env`, Telegram token, session secrets, deploy keys, SQLite/WAL-файлы, `/data`, backups, пользовательские CSV, временные файлы и логи.
- Исключить из Docker build context `.git`, `.venv`, локальные данные, backups, тестовые артефакты и секреты через `.dockerignore`.
- Считать ветку `main` всегда пригодной для развертывания; небольшую работу вести в feature-ветках, а проверенные версии отмечать тегами `v0.1.0`, `v0.1.1` и далее.
- Настроить GitHub Actions на каждый push/PR: установка из lock-файла, проверка форматирования/линтинга, тесты, контроль миграций и проверочная сборка Docker image. Workflow не получает production-секреты и не выполняет deploy.
- Подключить приватный репозиторий в Dockhand отдельным read-only deploy key, отслеживать ветку `main`, использовать `compose.yaml` из корня и включить `Build images on deploy`.
- Выполнять production deploy вручную в Dockhand после успешного CI. Не включать auto-sync и webhook в первой версии, чтобы ошибочный push не обновлял семейное приложение и не требовал публичного доступа к Dockhand.
- Не редактировать Git-managed Compose и исходники только в UI Dockhand: любые постоянные изменения сначала фиксируются в GitHub, затем подтягиваются на Synology.
- Хранить runtime-секреты исключительно в настройках/секретах Dockhand, а рабочие данные — только в постоянном каталоге Synology и его резервных копиях.

## Доменная модель и правила

### User

- Имя, логин, роль `admin` или `member`, состояние активности.
- Хеш пароля; исходный пароль никогда не хранится.
- Telegram ID и дата привязки, если Telegram подключен.
- Без привязанного Telegram пользователь сохраняет полный доступ к web-интерфейсу, но не участвует в автоматической рассылке.
- Администратор управляет аккаунтами; оба типа пользователей работают с общим списком.

### Group

- Название, Bootstrap Icon/emoji, приглушенный цвет и порядок сортировки.
- Все группы видны всем пользователям.
- Системная группа «Без группы» существует всегда и не удаляется.
- При удалении обычной группы пользователь обязан выбрать группу для переноса ее именинников.

### Birthday

- Полное имя, день, месяц, необязательный год, группа, заметка, состояние активности.
- День, месяц и год хранятся отдельно, чтобы не использовать фиктивный год для неизвестного возраста.
- Будущий год рождения запрещен; дубликат имени и даты вызывает предупреждение, но может быть сохранен осознанно.
- Если год неизвестен, возраст нигде не выводится.
- Для 29 февраля в невисокосный год напоминание по умолчанию отправляется 28 февраля.
- Вместо физического удаления основной сценарий предлагает архивирование; окончательное удаление требует подтверждения.

### Reminder и Delivery

- Правила первой версии общие: `7`, `1` и `0` дней до события, время `09:00`, зона `Europe/Moscow`.
- Получателями являются все активные пользователи с привязанным Telegram.
- Каждая попытка доставки фиксирует событие, год наступления, интервал, пользователя, статус, число попыток и ошибку.
- Уникальный ключ «именинник + дата наступления + интервал + пользователь» исключает повторную успешную отправку.
- Планировщик запускается регулярно, а не только один раз ровно в 09:00, и обрабатывает допустимое окно пропущенных заданий после перезапуска NAS.
- Временные ошибки Telegram повторяются с ограниченным backoff; постоянная ошибка отражается в журнале администратора.

## Web-дизайн и пользовательские сценарии

### Визуальная концепция

Интерфейс должен ощущаться теплым и праздничным, но оставаться спокойным рабочим инструментом: светлый теплый фон, темная хорошо читаемая типографика, один основной акцент, приглушенные цвета групп и небольшие уместные праздничные детали. Не использовать мозаику одинаковых dashboard-карточек, декоративные градиенты, толстые рамки и лишние тени.

Использовать Bootstrap 5.3.x и Bootstrap Icons, закрепленные по конкретным версиям и размещенные локально в Docker image. Отдельная Node/Vite-сборка для MVP не нужна: Jinja, HTMX, Bootstrap bundle и небольшой собственный CSS/JavaScript достаточны.

### Основные экраны

1. Вход и принятие закрытого приглашения.
2. «Ближайшие» — следующая дата как главный визуальный акцент и компактная хронологическая лента последующих событий.
3. «Все дни рождения» — поиск, фильтр по группе/месяцу и сортировка по ближайшей дате.
4. Добавление и редактирование именинника.
5. Управление группами и их порядком.
6. Профиль — подключение/отключение Telegram, тестовое сообщение и выход со всех устройств.
7. Администрирование — семейные аккаунты, приглашения, состояние Telegram-привязок и последние ошибки доставки.

### Mobile-first требования

- Сначала проектировать ширины 320–430 px, затем расширять композицию для tablet/desktop.
- На телефоне использовать нижнюю навигацию «Ближайшие / Все / Настройки» и постоянно доступное действие добавления.
- Формы строить вертикально, с явными `label`, короткими подсказками и кнопкой сохранения во всю доступную ширину.
- Все интерактивные цели делать не меньше примерно 44×44 px.
- Не допускать горизонтального скролла, hover-only действий и критичных функций в мелких выпадающих меню.
- Учитывать экранную клавиатуру, safe-area, увеличение системного шрифта и длинные русские имена.
- На desktop использовать более плотный список и верхнюю навигацию, сохраняя тот же порядок действий.
- Проверить контраст уровня WCAG AA, клавиатурный фокус, screen-reader labels и `prefers-reduced-motion`.
- Анимации ограничить коротким появлением обновленного списка, аккуратным открытием формы и ясной обратной связью на нажатие.

### Формы

- Основная форма: имя, день/месяц, необязательный год, группа, заметка и активность.
- Ошибки показывать рядом с полем и связывать через `aria-describedby`/`aria-invalid`.
- Клиентская проверка улучшает обратную связь, но окончательная валидация всегда выполняется сервером.
- После сохранения показывать понятное подтверждение и следующий логичный шаг.
- Пустые состояния должны объяснять действие, например «Пока никого нет — добавьте первый день рождения».

## Telegram-бот

Бот использует короткие сообщения, emoji как навигационные маркеры и inline/reply-кнопки. Emoji дополняют текст, но не заменяют подписи.

Главное меню:

- `🎂 Добавить`;
- `📅 Ближайшие`;
- `👥 Все`;
- `🏷 Группы`;
- `⚙️ Настройки`.

Основные сценарии:

- `/start` объясняет назначение и предлагает безопасно привязать семейный аккаунт.
- Привязка выполняется одноразовой ограниченной по времени ссылкой/кодом, созданным в web-профиле.
- Добавление проходит шаги «имя → дата → год или пропустить → группа → заметка или пропустить → предпросмотр → сохранить».
- На каждом шаге доступны `↩️ Назад` и `✖️ Отмена`; состояние незавершенного сценария имеет срок жизни.
- Поддерживается быстрый ввод вида «Иван Петров 17.05.1985» с обязательным предпросмотром перед записью.
- Список и поиск возвращают компактные результаты с кнопками `✏️ Изменить`, `🗑 Архивировать`, `🌐 Открыть`.
- Напоминание содержит имя, дату, возраст при наличии и группу; доступны `🌐 Открыть` и `⏰ Напомнить вечером`.
- Все callback-данные проверяются на сервере; Telegram ID без активной привязки не получает доступ к данным.

## Авторизация и безопасность

- Создать первого администратора отдельной CLI-командой или одноразовым bootstrap-механизмом, а не стандартным паролем в образе.
- Использовать Argon2 для паролей, закрытую регистрацию, срок жизни приглашений и возможность их отзыва.
- Использовать серверные сессии или подписанные session-cookie с `Secure`, `HttpOnly`, `SameSite=Lax`, ротацией после входа и функцией выхода со всех устройств.
- Добавить CSRF-защиту всем изменяющим web-запросам и ограничение попыток входа.
- Проверять `Host` и `Origin`; доверять forwarded-заголовкам только от обратного прокси.
- Не выводить пароли, Telegram token и session secrets в логи.
- Публиковать контейнерный порт только как `127.0.0.1:8787:8000`; наружу на роутере открывается только HTTPS-порт Synology.
- Не публиковать SQLite, Docker API, Dockhand и служебные endpoints.
- Добавить `/health/live` и `/health/ready`; подробности внутренних ошибок не возвращать публичному клиенту.

## Docker, Dockhand и данные

- Подготовить `Dockerfile`, `compose.yaml`, `.gitignore`, `.dockerignore` и `.env.example` без секретов.
- Использовать официальный slim Python image с закрепленной версией и запускать приложение от непривилегированного пользователя.
- Хранить данные в настраиваемом bind mount, рекомендуемый путь Synology — `/volume1/docker/happyday/data:/data`.
- Задать `TZ=Europe/Moscow`, `LANG=C.UTF-8`, `PYTHONUTF8=1`, `APP_BASE_URL` и Telegram token через окружение/секреты Dockhand.
- Добавить `restart: unless-stopped`, healthcheck и ограниченную ротацию Docker-логов.
- Использовать версионированные теги образа; не включать бесконтрольное автообновление `latest`.
- Перед миграцией автоматически создавать согласованный backup через SQLite Online Backup API. Hyper Backup должен копировать готовые снимки из `/data/backups`, а не только активный файл БД.
- Создать в Dockhand Git Stack с read-only доступом к GitHub, ручным deploy и локальной сборкой image на Synology.
- Документировать создание Git Stack в Dockhand, ручное обновление, просмотр логов, backup, восстановление и откат образа/коммита.
- Документировать параметры DSM Reverse Proxy, но не автоматизировать домен и сертификат: ими управляет владелец Synology.

## Тестовая матрица

- Календарь: конец месяца/года, високосный год, 29 февраля, неизвестный год, вычисление возраста.
- Планировщик: обычный запуск, повторный запуск, простой NAS, пропущенное окно, временная ошибка и достижение лимита retry.
- Доставка: личное сообщение каждому пользователю с привязанным Telegram, отсутствие отправки непривязанным и корректная обработка отключенной привязки.
- Авторизация: просроченное приглашение, неверный пароль, заблокированный пользователь, CSRF, отзыв сессий и Telegram-привязки.
- Данные: русский текст, `ё`, emoji, длинные имена, CSV с UTF-8 BOM и без BOM, предупреждение о дубле.
- Интерфейс: мобильные размеры, поворот экрана, увеличение шрифта, клавиатура, фокус, reduced motion и пустые состояния.
- Эксплуатация: чистая установка, повторный deploy, миграция с backup, восстановление SQLite и откат контейнера.
- Git workflow: чистое создание `.venv`, установка строго из lock-файла, успешный CI, ручной deploy из `main` и отсутствие секретов/данных в истории репозитория.

## Критерии готовности MVP

- Семейный администратор может создать аккаунты, группы и первый список именинников без ручного обращения к БД.
- Любой активный пользователь видит одинаковый полный список и может найти запись не более чем за несколько действий.
- Добавление именинника одинаково понятно в мобильном web и Telegram; незавершенный бот-сценарий можно безопасно отменить.
- Пользователь с привязанным Telegram получает личные сообщения; пользователь без Telegram продолжает полноценно пользоваться web-интерфейсом без автоматических уведомлений.
- Повторный запуск приложения не создает дубликаты уже отправленных напоминаний.
- Интерфейс полноценно работает от 320 px, не имеет горизонтального скролла и проходит основные проверки доступности.
- Русский текст корректно сохраняется, отображается, экспортируется и импортируется без проблем с кодировкой.
- Stack запускается через Dockhand одной операцией, переживает перезапуск NAS и сообщает состояние через healthcheck.
- Есть проверенная процедура backup/restore и документированный безопасный откат версии.
- Репозиторий проходит GitHub Actions без production-секретов, а Dockhand вручную развертывает тот же проверенный commit из `main`.

## Данные, необходимые перед развертыванием

- Публичный `APP_BASE_URL` на выбранном поддомене.
- Telegram Bot Token, созданный через BotFather.
- URL приватного GitHub-репозитория и отдельный read-only deploy key, сохраненный в Dockhand.
- Фактический путь Synology для постоянных данных, если он отличается от `/volume1/docker/happyday/data`.
